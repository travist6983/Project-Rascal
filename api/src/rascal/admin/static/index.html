Membership — move a household's trial

The one entitlement lever, and deliberately the only one. Set the date to yesterday to see the free tier; set it forward to come back. It cannot set the tier — App Store Server Notifications are the only writer of that column, and a button here that disagreed with Apple would be worse than no button. Clearing the date leaves the household on free with no trial at all.

A household already on subscribed will not move, because subscribed beats trial. The date is still saved — it matters the day the subscription lapses — but access stays subscribed. Your own household is one of these: set tier back to free with the statement in runbook-deploy.md §7a first, then use this.

Grants — entitle a household without a payment

A founding tester, a refund made good, a family who should not be paying. A grant entitles a household exactly as a subscription does, and it does not touch the tier — a free household goes on reading free, because that column is what Apple said and nothing here can be a second voice in it. What moves is entitled, which is what every gate reads.

Leave the end date empty for a grant with no end. That is a real state rather than a missing one. Extending somebody is a new grant, not an edit — the ledger below is the history and it is the point.

The console is reading another database and is read-only, so grants cannot be issued or revoked from here. Unset ADMIN_READ_DATABASE_URL to edit against your local database, or use the deployed console.
